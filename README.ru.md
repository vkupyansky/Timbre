# Timbre

Telegram-бот с локальными моделями для русской речи. Превращает текст в голосовое выбранным голосом. Входящее голосовое сначала распознаётся, затем озвучивается тем же голосом и с его настройками.

## Возможности

- Личные голоса и настройки каждого разрешённого пользователя.
- Добавление голоса по 15–20 секундам чистой речи, до трёх образцов одного человека.
- Сравнение нового примера с прежним перед применением изменений.
- Настройки подачи, скорости, инструкции и параметров синтеза у голоса.
- Отдельный статус каждого задания с отменой и повтором доставки.
- Локальные Fish S2 Pro BF16 через MLX и Whisper-small через MPS.

## Установка и запуск

Нужны macOS на Apple Silicon с Metal/MPS и Docker Desktop. Нативный обработчик моделей готовится один раз по [инструкции установки](docs/architecture.md#первичная-установка). Linux-контейнер не получает доступ к Apple GPU.

Создайте `.env` по образцу [.env.example](.env.example):

| Параметр | Назначение |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | Токен бота от BotFather |
| `TELEGRAM_ADMIN_USER_IDS` | Положительные числовые Telegram ID через запятую |

Файл должен принадлежать пользователю сервиса и иметь права `0600`. Без корректных значений приложение не запускается. Внутренний ключ создаётся автоматически один раз.

```sh
docker compose up -d --build
```

Compose запускает приложение и SQLite. Пользовательская служба macOS запускает модели при входе в систему и ждёт приложение. Mac должен быть включён, пользователь должен оставаться в системе, Docker Desktop должен работать.

После изменения `.env` пересоздайте контейнер:

```sh
docker compose up -d --force-recreate
```

Готовый сервис можно разместить отдельно от исходников и запускать без `--build`. Служебный каталог с моделями, ключами и данными удалять нельзя. [Размещение и перенос сервиса](docs/architecture.md#исходники-и-установленный-сервис).

## Использование

1. Откройте личный чат с ботом и нажмите `/start`.
2. В разделе "Мои голоса" нажмите "Добавить голос", отправьте 15–20 секунд чистой русской речи одного человека и задайте название.
3. Дождитесь подготовки профиля и прослушайте пример. Готовый голос можно выбрать и настроить в его карточке.
4. Отправьте текст или голосовое. Бот пришлёт обычное голосовое сообщение.

Единственная команда `/start` переносит главную вниз чата. Остальное управление работает кнопками в одной панели. У каждого запроса отдельное короткое сообщение со статусом, отменой и при необходимости повтором отправки.

Голоса, выбранный профиль и настройки разделены по пользователям. Доступ имеют только ID из `.env`; посторонним бот не отвечает и не скачивает их файлы. Даже администратор не получает доступ к чужим голосам через интерфейс.

Настройки сохраняются у голоса. Изменение образцов сначала создаёт отдельный кандидат и пример; до подтверждения действует прежний набор. Дополнительные образцы служат контекстом модели, веса не обучаются.

В чистой установке добавьте собственный голос. Частные записи не поставляются с репозиторием. Необязательный локальный стартовый профиль копируется в независимые личные профили; удалённая пользователем копия не создаётся заново.

Для ударения можно выделить гласную: `замОк`, `зАмок`. Букву `ё` лучше писать явно. Это подсказка модели; результат нужно проверять прослушиванием.

## Проверки

Используются Python 3.12 и `uv`. Точные зависимости закреплены в [uv.lock](uv.lock) и [ml/uv.lock](ml/uv.lock), ревизии моделей в [манифестах](models/).

```sh
uv run --frozen python -m scripts.check
```

Команда проверяет форматирование, линтер, строгие типы, тесты с предупреждениями как ошибками, зависимости, сборку и изолированный запуск контейнера. Рабочий бот не получает сообщений. Реальные ML-проверки описаны в [тестировании](docs/testing.md).

## Ограничения

Текст и расшифровка ограничены 2000 символами, входящее голосовое: 120 секундами и 10 МиБ, результат: 180 секундами и 20 МиБ. Одно задание ограничено 15 минутами; модели выполняют задания последовательно.

Паузы, темп и эмоции входящей записи не копируются. Сходство с голосом, произношение и действие эмоциональных настроек требуют прослушивания. Таймаут Telegram может означать уже выполненную отправку; неоднозначная доставка требует решения пользователя.

Модели работают локально; сообщения и аудио передаются через Telegram. Профили и SQLite сохраняются в `.shift/`. История текстов и настроек хранится постоянно; временные записи, результаты и черновики очищаются в течение 24 часов. Подробнее в [описании данных](docs/data.md).

Оплата не подключена. Разрешённые администраторы пользуются ботом без списания времени; учёт прежних аккаунтов сохраняется при обновлениях.
