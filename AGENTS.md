# Timbre: правила разработки

## Навигация

- `src/shift/`: Telegram-интерфейс, внутренний API, очередь, данные и обработчик.
- `ml/`: локальные Fish TTS и Whisper ASR, отдельное окружение и тесты.
- `models/`: закреплённые ревизии, размеры и SHA-256 моделей.
- `scripts/`, `tests/`: установка службы, сборка и изолированные проверки.
- [Архитектура](docs/architecture.md), [данные](docs/data.md), [подготовка голоса](docs/profile-asr.md), [тестирование](docs/testing.md), [состояние](STATUS.md).

## Инварианты

- Сохраняйте существующие данные и поведение. SQLite меняется миграциями; удаление базы не исправляет миграцию. Резервные копии создаются только по отдельному заданию.
- Не включайте `.env`, `.shift/`, базы, аудио, веса, отчёты и персональные данные в Git, образы или дистрибутивы.
- Единственный `.env` содержит `TELEGRAM_BOT_TOKEN` и `TELEGRAM_ADMIN_USER_IDS`, без запасных переменных. Внутренний ключ создаётся атомарно один раз; секреты имеют права `0600`, каталоги `0700`, значения не попадают в логи и аргументы команд.
- Доступ разрешён только ID из `.env` в личном чате. Отклоняйте посторонних до записи аккаунта, скачивания файлов и создания заданий. Все действия повторно проверяют владельца; администратор не получает чужие профили. Удаление ID из списка отменяет его незавершённые задания, сохраняя историю.
- Голосовой ввод проходит через Whisper и Fish TTS выбранного голоса. Не выдавайте исходную запись за результат. Контракты образцов, сравнения кандидата и применения изменений закреплены в [подготовке голоса](docs/profile-asr.md).
- Единственная команда `/start` переносит главную вниз. Навигация редактирует одну панель, голоса показаны по две кнопки в ряд. Задание получает отдельный статус с отменой и повтором доставки; настройки сохраняются у голоса.
- История сохраняет неизменяемый снимок текста и настроек. Состояния генерации, доставки и списания разделены; повтор доставки не списывает время. Неоднозначный таймаут Telegram не разрешает автоматический дубль.
- Не добавляйте внешние сервисы синтеза, новые движки или fallback без задачи. Сохраняйте приватный акустический контекст шёпота. Качество и сходство проверяются прослушиванием.

## Проверки и сопровождение

Используйте Python 3.12, `uv` и существующие lock-файлы. Сохраняйте строгие типы и предупреждения как ошибки. Основная команда находится в [README](README.ru.md#проверки), полный порядок в [тестировании](docs/testing.md).

Проверки не используют рабочие токены и БД, не отправляют сообщения и не пересоздают рабочий сервис. Реальные ML-сценарии выполняйте изолированно и последовательно, не занимая порт работающего приложения.

Обновляйте связанные документы вместе с поведением. README описывает использование, STATUS текущее состояние; подробные контракты находятся в `docs/`. Не публикуйте приватные записи, локальные пути и историю отладки. Удаляйте заменённый код, сиротские настройки и неиспользуемые зависимости в рамках изменения.
