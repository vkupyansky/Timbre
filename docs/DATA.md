# Данные и отчёты

Рабочая база: `.shift/data/shift.sqlite3`, SQLite v9. Открывайте её в режиме чтения. Файл содержит персональные данные и тексты сообщений; он не входит в репозиторий. Права файла: `0600`, каталога: `0700`.

В боте пользователь видит собственный профиль и голоса. Локальный владелец файла БД может составлять отчёты по всем аккаунтам. Отдельного раздела истории в боте нет.

## Состав данных

| Представление | Содержимое |
| --- | --- |
| `report_users` | ID, имя, username, роль, баланс, выбранный голос, дата регистрации |
| `report_voices` | Личные голоса, имя, актуальные настройки, число образцов и текущий выбор |
| `report_generations` | История: пользователь, время, голос, текст, настройки, результат, длительность и расход |

Представления читаются SQL без загрузки файлов профилей. Основные таблицы: `accounts`, `profile_owners`, `voice_metadata`, `generation_history`, `job_billing`. Роли обновляются из списка администраторов в `.env`; редактирование таблицы не является способом настройки доступа.

Имя и username поступают от проверенного отправителя Telegram и обновляются при его взаимодействии. Неизвестное значение остаётся пустым. Постоянный идентификатор аккаунта: числовой ID, а не username.

При генерации сохраняются исходный текст или успешная расшифровка, ID и имя голоса, полный снимок настроек, отпечаток образцов, состояния генерации и доставки, причина ошибки, длительность проверенного OGG и списанные миллисекунды. Последующее изменение или удаление голоса не переписывает историю. Расшифровка фиксируется до синтеза и остаётся после его ошибки.

`kind='tts'` обозначает текстовый ввод, `kind='vc'` обозначает голосовой ввод через ASR и TTS. Типы `profile` и `reference` относятся к подготовке профиля и образцов. Имя `vc` сохраняется как контракт БД и не означает прямое преобразование тембра.

Администраторы освобождены от списания. Учёт обычных аккаунтов сохраняется для прежних данных. Списание фиксируется после проверки готового результата; повторная доставка не списывает время ещё раз. Ошибка доставки хранится отдельно, автоматический возврат за отказ Telegram после успешной генерации не реализован. Оплата отсутствует.

## Хранение и обновление

История текстов и настроек не имеет автоматического срока удаления. Она сохраняется при перезапуске, удалении голоса и суточной уборке заданий. Временные исходники удаляются после обработки, готовые аудиофайлы и черновики очищаются в течение 24 часов. Старая запись истории поэтому не гарантирует возможность повторно получить сам звук.

Неизвестные поля старой истории остаются `NULL`; `historical=1` отмечает записи до введения постоянных снимков. Нынешние настройки и повторное распознавание не подставляются вместо неизвестного прошлого.

Обновление сохраняет SQLite и файлы профилей в `.shift/data/`. База не содержит сами WAV: их связь с профилями должна сохраняться при переносе. Нельзя удалять БД для исправления миграции или копировать только её, ожидая получить работающие голоса. Резервные копии создаются только по отдельному заданию и также содержат приватные данные.

Тексты, записи и персональные данные не выводятся в технические логи. Выгрузки отчётов остаются защищёнными локальными файлами и не публикуются вместе с кодом.

## SQL-запросы

Пользователи и остаток времени:

```sql
SELECT user_id, username, display_name, is_admin,
       balance_ms / 1000.0 AS balance_seconds,
       reserved_ms / 1000.0 AS reserved_seconds,
       selected_voice_name,
       datetime(created, 'unixepoch') AS registered_utc
FROM report_users
ORDER BY created DESC;
```

Текущие голоса пользователя, где `:user_id` является параметром запроса:

```sql
SELECT name, is_selected, is_default, speed, native_tags_json,
       style_instruction, temperature, top_p, top_k, seed,
       reference_count, profile_json
FROM report_voices
WHERE user_id = :user_id
ORDER BY is_selected DESC, name;
```

Последние 50 озвучек со снимком настроек:

```sql
SELECT datetime(created, 'unixepoch') AS created_utc,
       user_id, kind, profile_name, synthesis_text,
       voice_snapshot_json, generation_status, delivery_status, failure,
       duration_ms / 1000.0 AS audio_seconds,
       charged_ms / 1000.0 AS charged_seconds,
       preview, historical, job_id
FROM report_generations
WHERE kind IN ('tts', 'vc')
ORDER BY created DESC
LIMIT 50;
```

Для одного пользователя добавьте `AND user_id = :user_id` к условию последнего запроса. Время приведено в UTC. `NULL` означает отсутствие сведений, а не ноль.
