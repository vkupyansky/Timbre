# Архитектура и сопровождение

## Компоненты

Приложение aiogram/aiohttp и SQLite работают в Docker Compose. Нативный процесс `ru.shift.worker` на macOS получает задания через `127.0.0.1:8765`. У обработчика нет входящих сетевых портов. Он не читает Telegram-токен и использует отдельный внутренний ключ.

Fish S2 Pro BF16 выполняется через MLX, Whisper-small через MPS. Модели обрабатывают задания последовательно под общей блокировкой GPU. Голосовой ввод проходит через распознавание и обычный синтез; перенос исходных эмоций, пауз и темпа не выполняется. Текст ASR сохраняется в истории до запуска синтеза.

Docker не запускает модели на Apple GPU. Пользовательская служба launchd работает вне контейнера, поднимается при входе пользователя и ждёт Compose. `ProcessType=Interactive` соответствует обработке запросов, на которые пользователь ждёт ответа.

## Первичная установка

Эти действия выполняет разработчик один раз. Для обычного использования достаточно запуска Compose из README.

Требуются macOS на Apple Silicon, Metal/MPS, Python 3.12, `uv`, FFmpeg/FFprobe и Docker Desktop. BF16-модель требует значительного объёма объединённой памяти; рабочая конфигурация рассчитана на 24 ГиБ. Linux и Intel Mac не являются целевыми платформами обработчика.

Из корня проекта:

```sh
uv sync --frozen
uv run --frozen python -m scripts.service
```

Установщик создаёт закрытые рабочие каталоги и внутренний ключ, устанавливает зависимости ML по lock-файлу, загружает модели из закреплённых ревизий и проверяет SHA-256 всех файлов. Затем он устанавливает пользовательскую службу `ru.shift.worker`. Исправные загруженные файлы используются повторно; существующий внутренний ключ не заменяется.

Установщик требует доступные Python 3.12 и `uv`, не устанавливает Docker Desktop или FFmpeg. Его не нужно запускать перед каждой озвучкой. Если служба уже связана с другой рабочей папкой, установка останавливается, сохраняя её.

Перед запуском проверьте поле `user` в `compose.yaml`: UID/GID контейнера должны совпадать с владельцем `.env` и `.shift/`. Получить значения можно командами `id -u` и `id -g`. Исходное значение `501:20` подходит не всем учётным записям macOS.

Заполните единственный `.env` по README и установите права `0600`, затем выполните `docker compose up -d --build`. Закрытые каталоги `.shift/secrets` и `.shift/data` уже должны существовать после установки службы: Compose не создаёт их молча. В чистой установке голоса добавляются через бот. Частный стартовый голос не поставляется в репозитории.

## Конфигурация и границы доверия

| Расположение | Назначение |
| --- | --- |
| `.env` | Токен Telegram и единственный список разрешённых администраторов |
| `.shift/secrets/worker.token` | Внутренний ключ API, создаётся один раз |
| `.shift/data/shift.sqlite3` | Аккаунты, очередь, состояние интерфейса и постоянная история |
| `.shift/data/profiles/` | Личные профили, образцы, примеры и контекст шёпота |
| `.shift/data/default-voice/` | Необязательный частный шаблон стартового голоса |
| `.shift/data/reference-changes/` | Кандидаты изменения образцов до подтверждения |
| `.shift/data/profile-trash/` | Журнал восстановления файловых операций |
| `.shift/models/` | Загруженные и проверенные веса моделей |
| `.shift/work/` | Временные файлы обработки |

Секретные файлы имеют права `0600`, каталоги `0700`; проверяются владелец и отсутствие символьных ссылок. В контейнер `.env` монтируется только для чтения. Приложение работает без root, с read-only корнем, `cap_drop: ALL`, `no-new-privileges` и отдельными доступными для записи каталогами. Порт опубликован только на loopback. Docker socket не монтируется.

Telegram-вход ограничен личными чатами разрешённых ID. Чужое обращение отклоняется до записи аккаунта, загрузки медиа и постановки задания. Все операции с профилями и заданиями проверяют владельца. Устаревшая кнопка не заменяет актуальную проверку прав. После исключения ID незавершённые задания отменяются до дальнейшей обработки или доставки; его данные не удаляются.

Внутренний API требует Bearer-ключ. Операции задания дополнительно проверяют действующий lease, тип и размер входа, отмену и фактический формат аудио. Результат проверяется до перехода в готовое состояние. `/health` открыт только в пределах локально опубликованного порта и показывает доступность БД, недавний контакт обработчика и наличие профиля первоначального владельца. Этот ответ сам по себе не доказывает доступность Telegram или качество синтеза.

## Данные и восстановление

Текущая схема SQLite: v9. Изменения применяются последовательными миграциями. Первоначальный владелец сохраняется в БД; перестановка администраторов в `.env` не меняет принадлежность прежних голосов. Личные параметры и выбранный голос изолированы по Telegram ID. Настроенный стартовый шаблон копируется независимо для каждого аккаунта; удалённая личная копия не создаётся снова.

Задание сохраняет снимок настроек и собственные копии образцов. Позднее редактирование или удаление голоса не меняет уже поставленный запрос. Постоянная история отделена от временной очереди и переживает очистку аудио. Представления для отчётов описаны в [DATA.md](DATA.md).

Создание голоса проходит через черновик: образец, название, проверка и ASR, новая пробная озвучка, публикация профиля. При добавлении или удалении образца сначала сохраняются отдельный кандидат и пример. Только явное применение меняет действующий набор, сохраняя актуальные имя и настройки. Журнал файловой операции и транзакция SQLite позволяют восстановиться после прерывания.

Учёт длительности, состояние готового результата и списание фиксируются атомарно. Администраторы освобождены от списаний. Учёт прежних обычных аккаунтов сохранён для целостности данных; повторная доставка не создаёт новое списание. Платежи отсутствуют.

Перед отправкой аудио сохраняется намерение. Неоднозначная ошибка Telegram оставляет `uncertain`; повтор выполняется только по кнопке пользователя из готового файла. Telegram не гарантирует отсутствие дубля после потерянного ответа. При восстановлении прерванные `running` становятся `failed`, незавершённые `sending` становятся `uncertain`; ожидающие и готовые задания сохраняются.

## Интерфейс и уведомления

`/start` создаёт главную внизу, сохраняет её ID и удаляет предыдущую панель. Навигация и настройки редактируют эту панель. У задания отдельное сообщение состояния; отмена и повтор проверяют пользователя, задание и ID этого сообщения. Перенос главной не сбрасывает привязку статуса.

Намерение первой отправки статуса сохраняется до обращения к Telegram. Неоднозначная ошибка не вызывает автоматического дубля; явный ответ об ограничении частоты допускает повтор после указанной задержки. Удалённое уведомление не создаётся заново. Обновление подтверждается только для актуального ID и состояния задания; сообщения меню и статуса не делят один якорь.

Подсказки Fish и русские пояснения находятся в `src/shift/voice_controls.py`. Машиночитаемый перечень: [voice-controls-catalog.json](voice-controls-catalog.json). Подсказки не гарантируют слышимое действие для каждого голоса. Для шёпота используется также короткий акустический контекст в приватном профиле; он проверяется по образцам и ревизии модели и не входит в репозиторий.

## Проверки и обновление

```sh
uv run --frozen python -m scripts.check
```

Команда проверяет формат, линтер, строгие типы, тесты с warnings as errors, совместимость и известные уязвимости зависимостей, дистрибутивы, Compose и изолированный контейнер на отдельном порту. Она собирает образ, но не заменяет рабочий контейнер и не выполняет внешнюю отправку Telegram.

Реальная изолированная проверка локальных моделей требует собственные записи:

```sh
uv run --frozen python -m scripts.accept_local \
  --reference /path/to/reference.wav \
  --source /path/to/speech.ogg
```

Нужны подготовленные модели, собранный образ `shift:0.1.0`, образец 15–20 секунд и свободный порт 8765. Используется временная служба и локальный транспорт вместо Telegram. Не запускайте эту проверку поверх рабочего сервиса на том же порту. Она подтверждает прохождение цепочки, но не заменяет прослушивание и живую проверку Telegram.

При обновлении сохраняйте `.env` и всю `.shift/`. Новые секреты и профили не копируются между компонентами вручную. Нативная служба привязана к рабочему каталогу: изменение его пути требует отдельной переустановки службы. Резервные копии создаются только по отдельному заданию и не входят в Git.
